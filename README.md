# 哔哩清风 · BiliBreeze

根据偏好折叠 B 站动态与视频置顶评论中的广告、抽奖、活动宣传和招聘内容。支持 Chrome 与 Edge 浏览器，需自行配置 API 密钥。

## 安装与更新

1. 从 [Releases 页面](https://github.com/PosvdM/bili-breeze/releases/latest) 下载 `bili-breeze-版本号.zip`（无需解压）。
2. 在浏览器中打开 `chrome://extensions` 或 `edge://extensions`，开启「开发者模式」。
3. 将 ZIP 安装包拖入扩展管理页完成安装。
4. 打开扩展的「API」选项卡，填写服务地址、模型与 API 密钥并保存。

更新扩展时下载新版 ZIP 拖入扩展管理页覆盖安装，原有的设置、名单和历史记录会保留。更新后刷新 B 站页面生效。

1.0 与 1.0.1 版本的扩展 ID 未固定。升级到新版会识别为新扩展，需重新填写 API 设置与名单，并手动移除旧版本。1.0.2 起扩展 ID 已固定，后续更新直接覆盖即可。

## 选择要折叠的内容

在「过滤」选项卡中选择识别范围和折叠类别。设置自动保存，已折叠的内容可随时手动展开。

| 类别 | 内容 |
| --- | --- |
| 广告 | 商品推广、品牌宣传、带货营销等 |
| 抽奖 | 以奖品和参与方式为核心的抽奖 |
| 活动宣传 | 见面会、展会、演出、比赛等通知与邀约 |
| 招聘 | 正式员工、实习等岗位招录 |

广告判定输出置信度概率，不细分广告类型。官方账号介绍自家作品（如预告、实机演示、开发进展与版本更新）不判定为广告；含有优惠促销、周边带货或第三方品牌合作时判定为广告。作者名称仅作为判定参考，不作为免检白名单。

游戏历史低价推荐与折扣汇总属于消费资讯。仅包含价格、折扣幅度、普通商店链接或购买建议不判定为广告；存在赞助、返佣、推广码、代购或自营店铺导流等商业证据时判定为广告。

默认开启广告与抽奖折叠。开启「包含附带抽奖」后，会同时折叠新闻、活动等正文附带的抽奖。抽奖由关键词与模型共同判断；主次关系不明确时不予折叠。单条内容可同时命中多个类别。

## 调整过滤强度

广告置信度达到设定阈值时执行折叠。普通阈值默认为 **40%**；谨慎过滤阈值默认为 **90%**（用于减少误判）。支持通过滑块或数字调整，谨慎阈值不可低于普通阈值。

默认阈值定义于 `prompts/classification.js`，随内置 Prompt 调整。未修改过阈值的用户会自动应用新默认值，已自定义阈值的用户保留原有设置。

开启「自动谨慎模式」后，当同一 UP 主最近检测的 **10 条**动态中有 **40%** 判定为广告时，该 UP 主会自动加入谨慎过滤名单。样本条数与判定比例均可调整。加入名单后持续生效，即使后续广告占比下降也不会自动移出。

统计基于本机首次检测顺序计算，单条动态仅计一次。检测记录不足设定条数时持续积累；未获取 UID、视频置顶评论以及跳过识别的内容不计入统计。

## 修改识别 Prompt

「过滤」页面底部提供用于判定广告、招聘和活动宣传的内置 Prompt，支持直接编辑，上限 4,000 字，光标离开输入框时自动保存。清空输入框或点击「重置为内置 Prompt」可恢复默认 Prompt。

输出格式由扩展自动附加，不可修改；抽奖主次判断固定使用内置规则。修改 Prompt 后，内容会重新调用 API 进行识别并消耗额度；恢复内置 Prompt 后可复用同版本的识别缓存；内置规则更新后会自动重新识别。

从 1.0.3 升级时，已填写的补充规则会自动拼接到内置 Prompt 末尾予以保留。

## 管理 UP 主名单

- **始终显示（白名单）**：不折叠该 UP 主的任何内容，且不调用 API。
- **谨慎过滤**：使用更高的广告判定阈值；抽奖、活动宣传和招聘仍按对应分类开关处理。

添加方式：可在「名单」选项卡输入 UID 添加，也可在 UP 主个人动态页左侧「全部」「视频」下方点击快捷按钮。按钮会显示当前状态，再次点击即可移出名单。若两个名单同时启用且存在冲突，白名单优先生效。

名单同时显示昵称与 UID，UP 主更改昵称不影响匹配。昵称获取失败时保留 UID，可稍后重试。视频置顶评论按视频发布者匹配。

自动加入谨慎名单的条目标注为「自动添加」。关闭自动谨慎模式仅停止添加新条目；手动移出的 UP 主不会再次自动加入，需要时可手动添加。

## API 与数据

支持 Jev 与 OpenAI Chat Completions 兼容接口。Jev 直连 `api.typesafe.ai`；自定义服务需填写完整 HTTPS 接口地址、模型名称与 API 密钥，并确保浏览器有权访问该域名。

API 密钥仅保存在本地。识别时仅将文本、作者昵称、标题和内容链接发送给所选服务商，消耗用户的 API 额度。扩展不分析图片与视频。

识别结果在本地缓存 30 天，上限 5,000 条。调整过滤阈值或分类开关可复用缓存；动态内容、模型、接口或分类规则变更时会重新识别。

「记录与统计」保留最多 5,000 条去重记录，可查看分类、置信度与处理结果。统计数据仅代表本机已检测内容。大模型存在误判可能，可通过名单和阈值调整过滤效果；网络延迟或快速滚动页面时，折叠可能有短暂延迟。

## 仓库结构

- 根目录：扩展清单（`manifest.json`）、后台与页面脚本及样式，可直接作为未打包扩展加载。
- `prompts/`：分类规则（`classification.js`）、抽奖主次规则（`giveaway.js`）及 API 请求封装（`request.js`）。
- `docs/`：使用说明、测试说明与界面截图。
- `tests/`：自动化测试；`tests/helpers/` 加载后台脚本及其依赖。
- `scripts/`：打包脚本；`icons/` 与 `branding/`：扩展图标与项目图片。

修改分类规则后需在 `prompts/classification.js` 中递增 `CLASSIFICATION_VERSION`，避免复用旧判定。自定义 Prompt 会保留；若需应用新内置规则，在设置中重置 Prompt 即可。

## 开发与测试

环境要求：Node.js、Python 3，以及已安装的 Chrome 或 Edge 浏览器。

```sh
npm install
npm test
python scripts/package.py
```

扩展包生成在 `dist/` 目录，拖入扩展管理页即可安装。自动化测试使用模拟 API 响应，覆盖分类规则、名单、缓存、页面折叠与弹窗设置，不评估真实模型的分类准确率。详见 [测试记录](docs/TESTING.md)。
